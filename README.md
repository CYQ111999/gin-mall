# Gin-Mall 电商后台系统

**基于 Go + Gin + GORM + MySQL 的电商后端 API 项目**  
采用经典的分层架构，涵盖用户、商品、购物车、地址、订单等核心模块。

## 📖 项目简介

本项目是一个从零手写的电商后端 API 系统。在开发过程中，严格遵循 API -> Service -> DAO -> Model 的分层标准，旨在通过真实的业务场景（如订单的事务处理、库存扣减）来深入实践 Go Web 开发。

## 🛠 技术栈

| 分类 | 技术选型 |
| :--- | :--- |
| 后端框架 | Gin |
| ORM 框架 | GORM (V2) |
| 数据库 | MySQL 8.0 |
| 认证方案 | JWT (golang-jwt/v4) |
| 参数校验 | binding / validator |

## ✨ 核心功能模块（详细说明）

> 以下功能均已通过接口测试，并实现了严格的业务逻辑校验。

*   **👤 用户模块**：
    *   注册：直接存储明文密码（当前版本暂未引入加密，后续可扩展）。
    *   登录：验证用户名和密码，成功后发放 JWT Token。
    *   修改：支持修改用户名、密码、邮箱等信息。

*   **📦 商品模块**：
    *   发布：管理员或登录用户创建商品，包含名称、价格（以分存储）、库存、描述。
    *   列表：分页查询商品列表，支持按条件筛选。
    *   详情：根据商品 ID 查询商品详情信息。

*   **🛒 购物车模块**：
    *   加入：利用 MySQL **联合唯一索引**（user_id 和 product_id）配合 GORM `OnConflict` 实现重复加购时自动累加数量，避免重复记录。
    *   列表：通过 `LEFT JOIN` 商品表，一次性查出购物车商品名、单价、数量。
    *   删除：按购物车 ID 删除指定条目。
    *   详情：按购物车 ID 查询详细条目信息。

*   **📍 地址模块**：
    *   创建：添加收货人、电话、详细地址。
    *   列表：查询当前用户的所有收货地址。
    *   修改：修改已有的收货地址信息。
    *   删除：删除指定的收货地址。
    *   安全规范：所有操作均在 `Where` 条件中强制带上 `user_id` 校验，防止横向越权。

*   **📝 订单模块**：
    *   **创建订单**：利用 `db.Transaction` 开启数据库事务，实现订单主表、明细表插入以及商品库存原子扣减的一体化操作，任一环节出错自动回滚。
    *   **订单列表**：利用 GORM `Preload` 预加载获取订单商品明细，并利用独立结构体过滤内部敏感字段（如自增 ID）。
    *   **取消订单**：事务内修改订单状态为已取消，并恢复对应商品的库存数量。
    *   **支付订单**：模拟支付流程，通过 `WHERE status = 1` 的原子条件防止重复支付。

## 🎯 项目开发中遇到的坑与解决方案

在开发过程中，踩过不少 GORM 和业务逻辑的坑，以下是实际解决过的关键问题：

1. **GORM 表名不匹配问题**：数据库实际表名为复数（如 `carts`），但代码中使用了 `Table("cart")` 导致报错 `Error 1146: Table doesn't exist`。解决：统一检查并使用了正确的复数表名。
2. **GORM 联表查询 Scan 结果全为 0**：在 `Model(&Cart{}).Joins(...).Select("carts.cart_id...")` 时，GORM 无法将带表前缀的列名正确映射到临时结构体，导致所有字段返回零值。解决：改用原生 SQL `Raw` 或去掉 `Select` 中的表前缀。
3. **GORM 时间字段插入报错 1292**：插入订单时，`CreateAt` 和 `UpdateAt` 字段未赋值，导致 GORM 尝试插入 MySQL 默认拒绝的 `0000-00-00 00:00:00`。解决：在构建结构体时，手动为 `CreateAt` 和 `UpdateAt` 赋值 `time.Now()`。
4. **路由参数名不匹配**：路由中注册了 `/:productId`，但在代码里却用 `c.Param("id")` 获取，导致取到空字符串。解决：统一了路由参数名和代码中的读取名。
5. **JSON 参数绑定失败（中文乱码）**：在 `.http` 文件中发送 JSON 请求时，未添加 `Content-Type: application/json` 请求头，导致包含中文的字段被 `binding:"required"` 拦截，返回参数错误。解决：测试时显式添加对应的 Content-Type。
6. **订单列表查询数据重复**：直接用 `LEFT JOIN` 查询订单关联表，导致一个订单因包含多个商品而返回多条重复数据。解决：改用 GORM 的 `Preload` 预加载功能，实现了主表只查一次。
7. **中间件获取用户 ID 时大小写错误**：中间件 `c.Set("user_id", ...)`，但在 API 层却用 `c.Get("userId")`，导致无法获取到当前登录用户 ID，被误判为未登录。解决：统一了 `c.Set` 和 `c.Get` 的 Key 大小写。
8. **函数参数传反导致查询失败**：在调用 `GetCartById` 时，不小心把 userId 和 cartId 的传参顺序写反了，导致 SQL 去查错误的记录（查不到数据）。解决：梳理了参数含义，修正了传参顺序，并加日志打印辅助排查。
9. **假成功问题（RowsAffected）**：直接判断 `err != nil` 导致更新不存在的记录时不报错，返回假成功。解决：对 Update 和 Delete 操作增加 `RowsAffected == 0` 的判断，返回明确的业务错误。
